# ფუნქციების გეგმები (plans)

გეგმა ერთ დამტკიცებულ სპეციფიკაციას ამოცანებად შლის: ყოველი ამოცანა (`- [ ] T1 …`) ასახელებს, რომელ მოთხოვნას (REQ) და მიღების კრიტერიუმს ემსახურება და როგორ შემოწმდება; ცალკე წერია, რომელი gates უნდა იყოს მწვანე, როგორ დავბრუნდეთ უკან, და — თუ ორკესტრაცია ჩართულია — კოდის ციკლი (Sonnet 5.5 წერს, Opus 5.5 ამოწმებს, მაქს. 2 ბრუნი).

**ცხოვრების ციკლი:** `/feature-plan` ქმნის `PLAN-NNNN-slug.md`-ს (`draft`) → მფლობელი: `/approve plan NNNN` (`approved`) → აგენტი ასრულებს: `in-progress` → `done`. დამტკიცებულ გეგმაში აგენტს შეუძლია მხოლოდ ამოცანების მონიშვნა, სტატუსის წინ წაწევა და ჩანაწერის დამატება სექციაში `## გადახრები` (რა შეიცვალა შესრულებისას და რატომ). დანარჩენი ცვლილება = ხელახლა გახსნა და ხელახალი დამტკიცება.
